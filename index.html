Abstract

Geometry-aware rotary positional encodings, such as RayRoPE, help attention reason about the 3D spatial relationships between tokens and the query camera. However, they implicitly assume a static scene, encoding each key at its observed position regardless of when it was captured. For dynamic scenes with temporally separated input views, this mismatch places the same moving object at a different position in each input frame, so it can be rendered at an inaccurate position. While temporal encodings inform attention when a token was observed, they do not resolve where its content should be at the query time.

We introduce GALILEO, a simple and general approach that aligns positional encodings with dynamic scene geometry through Galilean transport. Before positional encoding, each key's 3D position is transported to the query time using its estimated velocity and the temporal offset. By modifying only key positions, GALILEO integrates directly with existing encodings, including RayRoPE and URoPE, without altering their formulations. Velocities can be obtained from arbitrary sources; by default, we estimate them from token correspondences within the network.

Integrated into LVSM, GALILEO improves dynamic view synthesis on Syn4D, dynamic Objaverse, and real-world Stereo4D videos over baselines. Ablations show that encoding velocities as token features yields smaller gains, while attention visualizations reveal that GALILEO attends to query-time locations of moving content, unlike RayRoPE. Beyond view synthesis, GALILEO also reduces tracking errors on dynamic objects in a pretrained 3D point tracker and improves moving-vehicle generation in a video generator.

Method

Temporal RoPE says when. Galilean transport says where.

Ray-based encodings such as RayRoPE and URoPE describe each key by 3D points along its camera ray, expressed in the query camera's frame. Those points are where the content was at capture time tb. For a query at another time ta, that is only right if nothing moved.

Limitations

By default GALILEO fits a constant velocity between adjacent frames, which does not follow content that accelerates or turns; 3D tracks or ground-truth motion can replace the estimate where available.

Depth and motion accuracy limit the transport. With ground-truth motion PSNRdyn on Syn4D rises by 1.38 dB over RayRoPE; with ground-truth depth as well, by 2.3 dB over RayRoPE at the same depth. The estimated velocities recover about two thirds of what ground-truth motion gives.

The full model relies on depth and motion supervision that unlabeled video does not provide. With the image loss alone, transport still gives 0.56 dB, 60% of the gain.
